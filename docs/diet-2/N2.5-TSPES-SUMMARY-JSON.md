# N2.5：`tspes.py` 增加 `--summary-json`（在 `tspes.py` 自己的仓库实现）

> 本文只写 ConfFlow 一侧的接口约定与建议的实现要点；`tspes.py` 在独立仓库，由你确认字段（方案 Q6）后在那里实现。ConfFlow 不解释摘要内容，只存储并让 JobDesk 以通用表格展示。

## ConfFlow 一侧已经就绪的约定（N2，已合并）

- 工作流里用 `executor: script`，`script: tspes`（`server.toml` 的 `[scripts.tspes]` 登记，`command = ["python3", "/path/tspes.py"]`）。
- 步骤的 `outputs.summary: "summary.json"`：脚本在**该任务的工作目录**里写出这个文件；退出码为 0 且声明的输出文件都存在才算成功。
- 摘要必须是 **JSON 对象**，大小 **≤ 1 MB**；ConfFlow 原样存入结果（`kind="script_summary"`），不做任何校验或解释。
- 占位符只有 `{input}`、`{cores}`、`{mem_gb}`、`{item_id}`；每个输入结构一个任务，输入写为 `input.xyz`。
- 续算：中断后在同一工作目录重新调用脚本，由脚本自己的指纹续跑跳过已完成部分（`tspes.py` 已有指纹续跑）；脚本内容改变视为新任务。

## 建议的摘要格式（待你确认，Q6）

每个输入输出一个 JSON 对象，建议字段：

```json
{
  "input": "input.xyz",
  "status": "ok",
  "ts_imag_freq": -412.7,
  "dG_act": 18.3,
  "dG_rxn": -4.1,
  "energies": {"reactant": -0.0, "ts": -0.0, "product": -0.0},
  "warnings": []
}
```

- `status`：`ok` / `partial` / `failed`；`partial` 与 `failed` 时在 `warnings` 里给出可读原因。
- 能量单位建议 Hartree，活化与反应自由能单位 kcal/mol，字段名里带单位后缀更稳妥（如 `dG_act_kcal`）。
- 缺失的量**省略键**，不写 `null` 或 `0`，与 ConfFlow 的 `energies` 约定一致。

## `tspes.py` 一侧的实现要点

1. 增加命令行参数 `--summary-json PATH`；不给则行为与现在完全相同。
2. 在每个输入的结果汇总处（现有写 `tspes_results_all.txt` 的位置）额外写出上述 JSON（建议 `sort_keys=True`、`indent=1`，保证重跑字节稳定）。
3. 写文件用“先写临时文件再 `os.replace`”，避免被取消时留下半个 JSON。
4. 退出码保持现状：成功为 0；脚本内部失败时仍写出 `status="failed"` 的摘要并以非 0 退出（ConfFlow 视为任务失败并附 stderr 末尾）。
5. 不要依赖 ConfFlow 的目录结构，只依赖当前工作目录与 `--summary-json` 给定的相对路径。

## 在 ConfFlow 工作流里的用法示例

```yaml
- id: refine_ts
  executor: script
  script: tspes
  args: ["{input}", "--nprocs", "{cores}", "--mem", "{mem_gb}", "--summary-json", "summary.json"]
  resources: {cores_per_item: 48, memory_per_item: 120GB}
  outputs:
    artifacts: ["*.log", "tspes_results_all.txt"]
    structures: "final.xyz"
    summary: "summary.json"
```

JobDesk 在“脚本步骤”表单里选择脚本 id（取自运行时能力 `registered_scripts`），运行结果里显示摘要表格。
