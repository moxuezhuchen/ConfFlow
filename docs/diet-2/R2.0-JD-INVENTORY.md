   `intent/catalog.py`（卡片目录与 calculation 归类）、`intent/model.py`

   `intent/projection_guard.py`（`_CARD_ROLES` 全集）——均不含化学语义。

   字符串（`editor/manifest.py:66` 等）与结果展示的 capability 透传
   （`runs/v4_results.py:217`，原样显示不解释）；`reaction_profile` 在 `src` 零命中，
   仅 `tests` 侧消费 producer 产物。R2.1 删除分析界面即"只读汇总"改造的一部分（§6）。
4. **ensemble / path_endpoints / named_structures**：作为 ConfFlow 输出形式/适配器
   概念，在 JobDesk **零引用**（§6）。`path_endpoints_requested` 信号与
   "conformer ensemble" 文案均为同名无关项，已逐一排除。

   （`test_confflow_v4_e2e.py:380-381`、`test_packaging.py:158`）。
   R2.2 删除 contract 段后，这两处测试需同步改（属 R2.4 跨仓范畴）。

   断言）。R2.2 删除后机器面板的目标字段与 replay 机器通道需同步下线。

   presenter 计算目标 `server_id`、J1 结构预览绑定缓存 `target`）已逐一排除（§7）。
7. **fixture-agent / fixture_agent / synthetic_producer**：精确匹配零引用（§8）；
   R1.1 可留在 R1。
8. **D4 能量字段核实结论（§9，事实陈述）**：解析层三键齐备但结果投影层为条件性发布；
   `run_result.json` 的 `results[]` 为 ResultRef（无 `value` 字段），能量数值只存在于

   `run_result.json` 获得任何能量**。因此必须有一张**在 R2.3a 之前合并**的 `logic` 卡，
   把电子能 / `gibbs` / `gibbs_correction` 写进每个计算结果条目。本卡只陈述该依赖结论，不设计。

## 9. D4 核实：能量字段（事实陈述 + 对 R2.3a 的依赖结论）

### 9a. 解析层：三键齐备（方案引用的两个文件属实，`9fc594b` 复核）

- Gaussian：`confflow/programs/gaussian/parsing.py:44-52`
  （`SCF Done`、`Sum of electronic and thermal Free Energies`、
  `Thermal correction to Gibbs Free Energy` 三正则 + archive 回退）。

- ORCA：`confflow/programs/orca/parsing.py:128-150`
  （`electronic` ← FINAL SINGLE POINT ENERGY；
  `gibbs_correction` ← G-E(el)；`gibbs` ← Final Gibbs free energy；
  逐行 last-wins）。`adapter.py` 调用。

### 9b. 结果投影层：条件性发布（事实）

`confflow/execution/profile_standard.py:138-160`（`_select_energies`）与
`:391-435`：`energy`（= electronic）、`gibbs_energy`、`gibbs_correction`
三个 `ScientificResult` **分别按 `is not None` 条件追加**：

- `opt`/`sp`（无频率段）：log 中无 Gibbs 行 → 只有 `kind="energy"` 结果，
  **无 `gibbs_energy`、`gibbs_correction`**；
- `freq`/`opt_freq`/`ts_freq`：三者齐备；缺失时按 `corr = free - energy` 派生。

### 9c. run_result.json 形态：ResultRef 无 value（事实）

- ConfFlow `producer/run_result.py:60-80`（`result_ref_entry`）：ResultRef 只有
  `result_id/kind/subject_structure_id/source_step_id/source_work_item_id/
  producer_digest/value_digest/identity_digest`（+ `origin`），**无 `value` 字段**。
- 能量数值仅出现在 reaction-profile 分组条目
  （`run_result.py:421-529`：`electronic_energy/gibbs_energy/relative` + `barriers`，
  缺失时 fail-closed 拒绝投影）。
- JobDesk `v4_results.py:53-60,470-491` 只展示分组成员的 `energies.*`，
  从不读取 `kind="energy"` 的逐计算结果——与 D4"JobDesk 只汇总"一致。

### 9d. 对 R2.3a 的依赖结论（本卡只陈述，不设计）

- **事实**：R2.3a 删除 `confflow/analysis/` 整个包后，`run_result.py:421-529` 的
  分组投影失去数据源（`reaction_profile` scientific results 不再产生），
  JobDesk 将无法从 `run_result.json` 获得**任何**能量（逐结果条目本就没有数值，
  分组条目也将不再出现）。
- **结论**：必须有一张**在 R2.3a 之前合并**的 `logic` 卡，把电子能 /
  `gibbs` / `gibbs_correction` 写进每个计算结果条目（即让 `results[]` 携带数值，
  或等效的可消费位置）。没有这张卡，R2.3a 合并后 JobDesk 结果页的能量汇总、
  N3 按能量筛选的上游数据源将同时断裂，且断裂不可逆（分组产物无法回算）。
- 该 `logic` 卡的 schema 形状、数值精度、缺失语义由该卡自行定义，本卡不设计；
  R2.2 的 contract 差异核对（§12）以 R2.2  itself 为准，不把该卡的变更计入。
