## Corrected shared decisions

1. **Import entity identity:** NEVER use `{geometry_digest: entity_id}` as an import map: it merges equal-geometry distinct entities. NEVER use `start_index` as scientific identity. Keep `import_xyz(text, *, source_name="<input>", entity_ids: tuple[str, ...] | None = None) -> StructureSet`. Fresh imports mint independent opaque entity IDs (UUID is acceptable at the import boundary); an explicit ID sequence binds user-supplied entities, with exact count validation. CLI/run import persistence records each named input's exact source content digest and ordered entity records/IDs before execution. Resume of the same raw bytes reloads those IDs; reordered raw XYZ without explicit IDs must fail identity validation or require a new import, never guess by geometry. Reordering typed records with explicit IDs preserves identity. Same entity may legitimately appear on multiple ports when its payload is identical; conflicting payloads for an ID fail. Path is provenance only. D owns importer and import persistence; B owns domain identity and digest support.
2. **Result identity:** add typed ResultRef and stable producer-scoped `result_id` to ScientificResult. Value digest remains value-only. Result identity must include producer context and a semantic output discriminator; different methods/producers/subjects are distinguishable. Production emitted/imported results require an ID; deterministic construction from complete producer/subject/kind semantic data is acceptable; never collapse two source records solely because their values match. Read-only legacy records must not silently become valid production refs. B defines identity + serialization, C stamps profile results, F stamps analysis. Cardinality is declared by the port: IDS may select multiple distinct IDs on MANY ports; only duplicate/ambiguous candidates for the SAME requested ID fail. Do not globally require exactly one result after all selectors.
3. **Structures:** transformations bind output results to output geometry entities; genuine measurements/passthrough retain input identity. Use explicit adapter/parser geometry intent/facts and output identity helpers, never TaskName/role runtime dispatch. Reaction lineage relationships must be explicit and validated; no blind role copying or first ancestor selection.
4. **Binding:** StepOutputs carries actual StepStatus and enough completion provenance. No separate duplicate ProducerStatus authority is needed. Assembly retains healthy-step items and scoped errors, and checks actual partial/failed/cancelled producer state. Caller must distinguish waiting/missing/error/legal-empty and never execute an errored current step. Valid MANY empty sets can complete only explicitly; do not ban all empty inputs.
5. **Atom mapping:** retain existing kind/reference concepts; add per-slot `permutations: Mapping[str, tuple[int,...]]` to express independent product/guess mappings. A single existing explicit permutation can be a clearly defined uniform shorthand, not a second authority. Normalize once to per-slot form. Both assembly and executor use the same mapping validation helper before element compatibility.
6. **Digests:** structure inputs include entity, geometry, effective charge/multiplicity AND freeze, group, role, parents/root. Result inputs include ResultRef and provenance as scientifically relevant. Locator/path/GUI/scheduler remain excluded. B owns version changes in fingerprint/work_item contracts. Old generations fail closed rather than being silently reused.
7. **Environment:** real binary/version and scientifically relevant explicit environment are measured for production reuse. Endpoint hostname/path and scheduler width are transport/operational provenance, not scientific identity. Exclude target locator from environment reuse identity when the measured execution environment is equivalent; version this rule. Unknown cannot silently stand in for verified equivalence. Pure executors record their implementation environment without requiring Gaussian/ORCA executable.
8. **Runtime registration:** A owns ExecutionRegistry and its descriptors. Expose `resolve_executor(capability)`, `resolve_profile(name)`, `resolve_check(name)`, `resolve_recovery(name, *, adapter=None)` and `resolve_program(name)` (or clearly documented equivalent names before integration). Descriptor and implementation registration must be one authority; existing PROFILES/CHECKS/RECOVERIES can supply implementations but application/batch/remote cannot independently consult them. Do not edit C-owned profile/recovery/program files to accomplish this. Opaque must actually execute if published. Stochastic requirement depends on the actual scientific capability (including GOAT), not only the broad calculation enum; don't indiscriminately reject seeds for calculation.
9. **Executor seam:** `execute(work_item, context, *, should_cancel=None) -> WorkItemResult` for all four executor implementations. Existing pure AnalysisExecutor core may remain, but its item adapter belongs in the analysis package, not scientific orchestration in application. C owns non-analysis implementations and context; D owns batch/persistence dispatch and application. Batch selects registry-resolved executor and shares claim/commit/publish, not bespoke scientific branches.
10. **Analysis aggregation:** default is ONE explicit whole-set aggregation WorkItem via existing SINGLE bindings. No new mandatory `per_group` document setting is needed to repair the bug. The pure analysis core may compute groups inside that WorkItem. If per-group work is later needed, it must be represented in typed binding/item contracts, not an application merge/copy loop. F owns analysis item adapter and partial acceptance semantics. No application copy of whole output to many items.
11. **Execution binding resolution:** implement in a new execution module (C owns), taking domain/execution types and explicit arguments; it must not import V4RunRequest or application. Planned binding fields win; request defaults fill missing fields; preserve env/target/walltime/executable identity. Expose a concrete function signature in C's report for D. Use measured environment. Target-side resolution for remote never requires local absolute paths to work remotely.
12. **Persistence:** D owns batch/application. No published-file early return before current item reuse checks. Strict item durable commit before verified StepResult publication, no gap exception. Status-only blocked diagnostics remain lifecycle/report data, never counterfeit durable publication. RunState is lifecycle only. All executors share store/reuse/publication. D passes real current attempt to C's ItemExecutionContext; C creates bounded-length collision-resistant hashed item directory and distinct attempt child. Native basename sanitize is presentation only. Do not encode unbounded nested logical keys directly as filename.
13. **Remote envelope:** existing remote envelope VERSION MAY AND MUST change if wire semantics change; do not freeze a broken V2 shape. E owns all remote files in wave 2, including envelope. Preserve ports for all input kinds, true step/item digests, refs/provenance, binding request and attempt reconciliation. The local/shared-fs transport is a testable delivery implementation, not proof of cross-host execution.
14. **Native scope:** installed ORCA is `/opt/orca611/orca` (6.1.1); Gaussian installation exists `/opt/g16` (read/execute may require approval via supervising tools). Inspect actual versions and official manuals; no guessed syntax or fabricated "native" fixtures. Gaussian native version support must be explicit. Native tasks can use task temp directories. Real JobDesk consumer is `/opt/jobdesk-v2-v4/src/jobdesk_v2/application/editor/contract/v4.py` and results consumer `application/runs/v4_results.py`; read and test the actual consumer, do not claim it is unavailable. Do not modify sibling repository without supervisor coordination.
