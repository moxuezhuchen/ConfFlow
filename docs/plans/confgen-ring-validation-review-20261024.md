# 翻环落地验证后的机制复核（2026-10-24）

结论：保持本次预注册决定——不落地当前“替换至多一半局部重嵌入”的方案。akugod 的正面结果仍值得保留，但尚不足以支持泛化。下一步更值得研究的是明确的结构适用范围，而不是立即开发更复杂的分配器或追加预算。

本次只读核对代码、PR 状态和结构分类，没有新增 xTB 计算。48 次验证的数字来自用户汇报及 PR #180 head `91ffc8ed` 的文档；未重新评分 814 上的原始运行。

## 1. “只在有可翻侧环时启用”已经是原型行为

`confgen_ring_moves.py:112–165` 已筛选饱和、无外部桥接、单固定连接点的 5–8 元环。egozuv 同样满足这套条件，因此原建议不足以区分收益与退步的体系。

用当前图构造器和 PR 的冻结算子重新扫描，得到：

| 体系 | 原型合格环 | 环的组成与连接 |
|---|---:|---|
| akugod | 4 | 全碳饱和六元环；各仅一个重原子外接支链；环内无 donor |
| egozuv | 2 | C4O 五元环；锚点 O 就是 donor，环直接参与配位 |
| TS1 | 1 | C4O2 六元环；3 个重原子外接支链 |
| Zr7 | 1 | C4O2 六元环；4 个重原子外接支链 |

机器可读结果：[拓扑复核](data/confgen-ring-topology-review-20261024.json)。复现脚本：`/opt/confflow-archive/experiments-20261024/ring-topology-audit/confgen-ring-validation-audit-20261024.py`（输入在同目录 `replay/`，重跑结果与本 JSON 逐字节一致），只加载冻结算子、构造图并分类，不生成或优化候选。

一个具体的新假设是：**限定到环内无配位 donor、仅一个重原子外接支链的饱和全碳六元环。** 这比体系名白名单有明确的结构含义；但它是观察结果后形成的规则，不是原实验预注册条件。

在目前四个体系里，新条件只留下 akugod。因此重新跑原四个体系即使全部通过，也主要是关闭了另外三个体系的算子，不能算泛化验证。应先固定规则，再选择其他满足条件、且没有用于制定规则的分子；原 akugod 用作重复性检查，egozuv 用作不误触发的回归。新体系也应先检查是否有尚未覆盖的不同环态，不能只按分子含环就期待获益。

这项窄适用范围验证比完整多锚点 CP 闭环求解更接近已有正面证据，因而优先级更高。CP 和螯合臂反射仍是不同的生成机制假设，不能用本次侧环结果直接背书。

## 2. 退步与机会成本：可信解释不等于完整因果归因

`confgen_ring_explorer.py:47–56,83–84` 确实先生成局部 DG 提案，再替换至多一半。egozuv 6/6 对的 cov3 下降、翻环 108 次只留下 15 个来源极小，支持当前替换用法不合适。

但替换后搜索池和后续父代已经分岔，未对被丢弃 DG 坐标做反事实优化。不能把全部下降精确归因于那些被替换提案，也不能把 92/108 对 15/108 直接当成低能收益比。停止落地只需要预注册门槛失败，不依赖证明唯一的退步原因。

“额外加翻环”也必须明确成本：

- 保持总预算，新增翻环最终会减少别处的优化机会，需要明示从哪个算子扣除。
- 提高总预算，则对照也需要同等新增优化预算，且单独报告含 release 的 CPU；不能只比较原预算基线后宣称效率提高。

因此暂不优先尝试无明确成本对照的追加提案设计，也不原样重复现有替换设计。

## 3. `origin` 无法完成命中归因

[identity.py:514–518](../../confflow/science/confgen/identity.py#L514) 中，重复极小被更低能量坐标更新时仍保留首次记录的 `m.origin`。该语义本身不构成搜索错误，但不能拿它当当前坐标的完整来源。

因此“24 次运行的最好池结构 origin 都不是 ring”不能排除：

1. 翻环改善了一个已知极小的坐标/能量，但旧 origin 被保留；
2. 翻环子代经过普通单转子或重嵌入，产生最终最好结构；
3. release 后的排序和搜索池最低不同。

PR 文档也明确承认发布集合谱系未完成追溯。合适的结论是：**目前未完成 Zr7 额外命中的机制归因，不据此宣称翻环提高了 Zr7 命中率。** 不能升级成“确定不是翻环贡献”。这一修正不影响本次不落地决定。

后续实验日志应区分首次发现来源与当前几何的产生请求，记录父代 ID/几何版本、请求算子、去重结果及 release 对应关系。保留原来的首次发现标签，增加事件记录；只覆盖 `origin` 会丢失另一部分信息，同样不足以重建谱系。
