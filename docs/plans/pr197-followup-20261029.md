## 任务 F1（P1）— 环境与其他轴同时变化时，不得走"只换环境"的推进

拥有文件：`confflow/persistence/reuse.py`、`confflow/execution/batch.py`、`tests/v4/test_arch_review_1029_resume_identity.py`。
用户决定（2026-10-29）：**严格拒绝**。只有环境是唯一变化的轴时，才推进登记并重算；环境之外还有任何轴变化，就拒绝并给出诊断，不启动计算、不改写登记。该规则对所有状态生效（PENDING、RUNNING-dead、COMPLETED、FAILED、INTERRUPTED），终态路径的旧缺口一并修复。

问题：`_first_mismatch()`（reuse.py:270）先返回 INVALIDATE_ENVIRONMENT，之后才比较定义、绑定 artifact、work-item 输入和 artifact 校验；batch.py:923 收到后直接调用 `refresh_for_new_environment()`，连输入和定义的登记一起覆盖。

修复：
1. reuse.py：环境不同时，继续检查剩余的轴（step semantic、artifact checksums、work-item digest、artifacts_verified）。只有它们全部一致，才返回 INVALIDATE_ENVIRONMENT；否则返回第一个非环境的不匹配（其 details 中可加 `environment_also_changed: True`）。provenance 仍然最先检查。更新模块 docstring 中的规则说明。
2. batch.py：在调用 `refresh_for_new_environment()` 之前做防御性检查，确认除环境外其他轴都一致，否则 fail closed（抛 PersistenceError）。这条防御分支也要有测试覆盖。
3. 测试：{PENDING, RUNNING-dead, COMPLETED, FAILED, INTERRUPTED} × {环境+输入, 环境+定义, 环境+artifact}。断言：拒绝（与单独改变输入/定义时的拒绝相同）、没有启动计算、登记身份（环境 / 输入 / 定义摘要）未改变、attempt 数未变。只改环境的已有用例必须继续通过。另加一个正常工作流用例：script → MLIP，参考 `/opt/ConfFlow/docs/reviews/data/pr197-verification-20261029/workflow-combined-change.py`。

回归：`test_v43_*.py`、`test_v45_resume*.py`、`test_repair_environment*.py`、`tests/test_execution_identity_resume.py`、`test_arch_review_launch_identity.py`，以及所有涉及 environment 变化的 resume 测试（grep `refresh_for_new_environment`、`INVALIDATE_ENVIRONMENT`）。如果已有测试依赖"环境+输入变化时级联重算"的旧行为，停下来报告，不要改那些测试。

## 任务 F2（P1）— 旧 MLIP 结果（无权威拓扑）不得被复用

拥有文件：`confflow/execution/registry.py`、`tests/v4/test_mlip_step_schema.py`（只改其中的版本断言）、新测试 `tests/v4/test_pr197_mlip_upgrade_reuse.py`。

问题：MLIP 契约版本仍为 `confflow.contract.executor.mlip.v1`（registry.py:719）。旧版本产生的结果（patch / working_topology 为空，能量没有 provenance）在 runner、模型、环境不变的情况下被判为 reuse_hit，下游继续使用丢失拓扑的结构。

修复：把 MLIP 契约版本提升为 `confflow.contract.executor.mlip.v2`。先确认这个版本号实际进入了哪个复用轴（producer provenance、environment digest，还是 step semantic digest），并在报告中写明。旧结果必须要么重新计算，要么带清晰的诊断拒绝复用（提示改用新的 run root）。不能静默命中，也不能改写旧历史。

测试：模拟"旧提交生成 → 新代码续跑"。做法：用当前代码跑一次 MLIP，再通过公开 store API / monkeypatch，把已存登记里的契约版本改回 v1（或用 v1 的身份登记一个 COMPLETED 结果），然后续跑。断言：没有 `reuse_hit`；结果要么被重新计算并带有拓扑，要么被明确拒绝。参考复核脚本 `docs/reviews/data/pr197-verification-20261029/upgrade-reuse.py`（位于 /opt/ConfFlow 下）。
