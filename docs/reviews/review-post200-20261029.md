结论：发现 3 个可独立复现的问题，均能把实际使用新程序/模型得到的结果登记在旧身份下，恢复旧文件后继续错误复用。因此本轮不能给出“运行身份与结果复用已闭环”的结论。它们有共同的架构原因，但修复位置和必要验证不同，分别编号。优先级 P1 表示应优先修复的科学结果正确性问题，不表示每次运行都会发生；触发条件均涉及文件在等待期间被替换或改写。

## W1 / P1：原生计算和 MLIP 在配额等待前检查程序，等待后没有复检

位置：
- `confflow/execution/work_item_executor.py:1200`：核对已解析命令的文件指纹。
- `confflow/execution/work_item_executor.py:676`：原生计算调用启动公共方法，没有传 `before_submit`。
- `confflow/execution/mlip_executor.py:551`、`:598`：MLIP 同样先检查、再排队，没有传最终检查回调。
- `confflow/execution/work_item_executor.py:1330`、`:1339`：真正的等待点在 `manager.acquire()`；框架已经提供取得配额后的检查接口。

触发：服务器资源被其他工作项占用；本工作项测量程序 A、通过文件指纹检查并进入配额等待；等待期间部署/替换了同一位置的程序 B；随后资源可用。

实际结果：原生计算和 MLIP 都启动 B。MLIP 的结果仍归属于 A 的运行身份。将程序恢复为 A 后，在原 run root 续跑直接复用 B 的结果。

独立复现采用真实 `ServerQuota`、真实进程监督与 `V4RunApplication`，只把外部科学程序替换为可观察的测试程序。以 quota 日志确认已进入等待，再用 `os.replace` 换程序，没有替换 acquire、身份比较或 submit 实现。

| 场景 | 实际结果 |
|---|---|
| MLIP：测量 A 后排队，换 B 再释放配额 | completed，能量 -10 |
| 恢复 A，同一 root 续跑 | reuse_hit，仍为 -10 |
| A，新 root 对照 | completed，能量 -5 |
| 原生计算：测量 A 后排队，换 B 再释放配额 | 实际启动日志为 B，仍 completed |

建议：保留同一次解析得到的 `ResolvedCommand`，把最终指纹检查放入公共启动方法的 `before_submit`，位于配额取得之后、`supervisor.submit()` 之前。检查失败必须释放配额并返回明确的失败；不要再次搜索 PATH。

验收：原生计算和 MLIP 分别在真实配额等待期间原地改写、原子替换、切换符号链接，释放配额后不得启动替换程序或发布它的结果；配额不能泄漏，修复环境后应能重试。保持现有多工作项/PATH 固定回归测试。

证据：`quota_launch_probe.py`、`quota-launch-results.json`、`quota-launch.log`。

## W2 / P1：脚本的最终检查漏掉实际启动的解释器

位置：
- `confflow/execution/script_executor.py:290`、`:298`：用步骤环境解析实际解释器，并在排队前检查其内容。
- `confflow/execution/script_executor.py:338`：排队后调用 `_verify_at_launch`，没有传实际解释器路径。
- `confflow/execution/script_executor.py:142`：最终只重新读注册身份和脚本内容。
- `confflow/execution/script_registry.py:174`：裸名注册解释器依旧按控制进程 PATH 解析。

触发：控制进程 PATH 中的注册解释器 A 与步骤 PATH 中的解释器 B 路径不同，但初始内容一致，因此允许启动；工作项进入配额等待后，只替换 B，A 和脚本都保持不变。

实际结果：最终回调重新核对 A，检查通过；实际执行 B 的新内容，并按原身份发布、复用结果。

独立复现：两个目录各放一份初始字节完全一致的解释器包装程序，注册命令使用裸名；只修改步骤 PATH 所选的那个文件。正常 V4 脚本产生的结构坐标 z 从预期的 1 变成 2。恢复原内容后，同 root 仍 `reuse_hit` 得到 z=2；新 root 对照得到 z=1。

建议：把实际启动路径带入 `_verify_at_launch`，在取得配额后再次验证该文件与预期的解释器身份。保留现有注册身份与脚本文件校验。

这不要求改变此前用户选定的“注册身份按控制进程 PATH 计算”规则，也不要求改变脚本身份摘要；需要补齐的是对实际启动文件的最终校验。原计划中“脚本已有 sha256 校验兜底”的表述，在上述等待场景下尚不成立。

验收：控制 PATH 与步骤 PATH 不同但内容相同的解释器仍可运行；只在排队期间更换步骤解释器，释放配额后必须拒绝，且不能启动、发布或错误复用其结果。

证据：`assets_quota_probe.py`、`assets-quota-results.json` 中的 `script` 场景。

## W3 / P1：MLIP 模型的测量身份与实际加载文件之间缺少约束

位置：
- `confflow/execution/environment.py:440`：模型和 refs 的文件内容参与环境身份。
- `confflow/execution/mlip_executor.py:558`：任务只携带可变文件路径，没有测量时的文件身份或不可变快照。
- `confflow/execution/mlip_runner.py:415`：worker 按该路径加载模型和 refs。
- `confflow/execution/mlip_executor.py:928`：runner 返回的 `model_sha256` 只是诊断信息，没有与测量身份核对。

触发：MLIP 测量了模型 A，进入配额等待；模型路径处的文件改为模型 B，解释器和 runner 均保持不变；资源可用后 runner 实际加载 B。

实际结果：B 的计算结果按 A 的身份完成登记。恢复 A 后，同 root 续跑错误复用 B。

独立复现保留同一解释器、同一 runner，只在真实配额等待期间改写模型文件。科学 fixture 从模型文件读数作为能量，并在 done 文件写真实的 SHA-256。

| 阶段 | 结果 |
|---|---|
| 测量模型 -5，等待期间改为 -10 | completed，能量 -10 |
| 恢复模型 -5，同 root 续跑 | reuse_hit，能量仍 -10 |
| 模型 -5，新 root 对照 | 能量 -5 |

这个缺口不会因 W1 的程序指纹检查修复而消失：解释器文件自始至终没有变化。模型场景已运行复现；refs 共享相同路径传递方式，属于代码上应一起审查的资产，未声称本轮已独立跑过 refs 场景。

建议：将运行使用的模型/refs 固定为不可变的本次运行输入，或者传递测量时的身份，在 worker 真正加载之前校验，并确保发布时实际使用的身份一致。多 worker 也须遵守。仅比对 runner 结束时重新读取路径计算的哈希，不能证明较早加载到内存的就是那个模型。

验收：固定解释器，在配额等待期间替换模型和 refs，应拒绝或使用已固定的原内容；绝不能按旧身份发布新内容的结果。还要覆盖多 worker 和恢复原文件后的续跑，避免产生可复用的污染结果。

证据：`assets_quota_probe.py`、`assets-quota-results.json` 中的 `model` 场景。

## 架构判断与本轮范围

现有 domain → 编译/装配 → execution → 持久化与 producer 投影的职责划分可以继续保留。持久化已经有生成代 fencing、逐项身份登记、结果校验与终态仲裁；本轮没有证据支持为解决这些问题重写调度器、改存储 schema，或重启已决定暂不做的 R6 性能改造。

本轮主要检查了命令解析和四类执行器、配额和进程监督、复用/拒绝规则、存储预检、generation 及取消仲裁、控制服务入口、结果清单和科学 profile/拓扑传播。ConfGen 在 worker 和每次 xTB 启动处还有指纹检查，代码路径与 W1 不同；没有将它误报为同一缺口。此前的注册 PATH 决策、R6 和 D3 保持现状，也没有仅因偏好重新列为缺陷。

最值得收敛的边界是“已经测量的启动输入”。当前代码分别保存命令、环境、脚本身份、模型路径，再由各执行器各自决定检查时机，容易出现本轮三种遗漏。建议在现有请求/上下文结构上集中携带这些已测量信息，并统一约束最终启动检查的位置；无需为此立即做全项目重构。

科学输出最低契约仍是已记录的后续设计项，本轮没有把可选输出行为未经证明地当作新 bug。测试覆盖和 LOC 门禁能守住已声明规则，无法证明这些时间窗口上的一致性，需要加入真实等待后再改变文件的行为测试。
